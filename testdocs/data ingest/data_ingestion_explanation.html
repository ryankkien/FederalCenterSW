Data source integration — working doc

CPARS Unclassified only
Contains CO/COR performance narratives and contractor response comments — the best qualitative summaries of how a contract actually went.
  • 1. Pull service contract numbers from SAM.gov API — confirm API availability for Navy-scoped contract list
  • 2. For each contract number, pull evaluation as HTML via authenticated session (Focal Point role) → parse into JSON
  • 3. Extract: ratings (quality, schedule, cost control, management, regulatory compliance), CO/COR narrative, contractor response narrative, period of performance, eval type (interim / final)
  • 4. Join to contract master record via contract_id
  • 5. Run narratives through LLM analysis layer; collect structured ratings
⚠ Does not apply to classified contracts — CPARS is unclassified only. Those contracts rely solely on IPMDAR + weekly reports.
Reference: CPAR Quality Checklist (DoW COR Handbook) — for generating example CPARS reports to test pipeline.
Fields: contract/order number · DUNS/PSC/NAICS · eval type · narrative quality criteria · rating definitions (Exceptional → Unsatisfactory)
IPMDAR Monthly cadence
Where most structured contract performance data lives — cost, schedule, EVM metrics — plus the Performance Narrative Report, a rich qualitative document produced per reporting period.
  • 1. Primary: Route all contractor IPMDAR submissions to reporting@navy.mil equivalent via CDRL — bypasses EVM-CR entirely for new contracts, files arrive directly as JSON + Word/PDF
  • 1b. Backfill / historical: PMO Analyst-role user downloads submission packages (CPD + SPD + narrative) from EVM-CR portal and drops into system — no public API exists
  • 2. Join to contract master record via contract_id
What comes in and how
CPD
Contract Performance Dataset
JSON — BCWS, BCWP, ACWP, ETC, EAC by control account. Direct ingestion, no OCR.
SPD
Schedule Performance Dataset
JSON — milestones, critical path, planned vs. actual dates.
Narrative
Performance Narrative Report
Word / PDF, defined in DID. OCR → NER → LLM pipeline.
ℹ EVM-CR has no programmatic read API — it is a web portal for credentialed DoW users. The "authorized API" framing should be dropped. Email intake is the correct primary path.
